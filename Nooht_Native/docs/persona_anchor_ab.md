# 人设锚点方案 A/B 对比（任务包第三节 3）

人设锚点：推理时可插拔的轻量模块（adapter/LoRA 式），
同一套底座权重，加载即开启，卸载即关闭，每次生成强制参考。
Lumenoo 必须完整支持；Veronoo、Soleinoo 可选。

## 方案 A：两套权重（`PersonaSchemeA`）

- 做法：base 权重与人设合并权重各存一份，切换时整体替换 state_dict。
- 优点：推理零额外开销，行为确定。
- 缺点：显存翻倍；不可插拔（换人设要换整套权重）；多角色需多套权重。

## 方案 B：可插拔（`PersonaAdapter`，主线）

- 做法：底座权重不变，只加 LoRA 式低秩适配器；`load()` 开启，`unload()` 关闭。
- 优点：同一套底座权重；可插拔、可叠加；显存只多低秩参数。
- 缺点：推理时多一次低秩乘法（开销小）；需保证每次生成强制参考。

## 结论

主线选方案 B（可插拔），方案 A 作为对照保留。
人设一致性测试：`persona_consistency_check` 对比开启/关闭两次生成，
开启时必须强制参考人设锚点文本。
